Before we start · the basics in one slide

GPS in one minute: it is a timing system

Every GPS satellite carries an atomic clock and constantly broadcasts, in effect, "I am satellite k, and this is exactly what time it is." Your receiver notes when each message arrives. The signal travels at the speed of light, so delay × c = distance. Distances to four satellites give your position (x, y, z) plus the error of your own cheap clock.
\[ \rho_k = c\,(t_{\text{receive}} - t_{\text{transmit},k}),\qquad 1\ \text{ns}\ \leftrightarrow\ 0.30\ \text{m} \]

So GPS needs to time-stamp radio signals to a few nanoseconds. Three hard problems are in the way:

  • The signal is extremely weak, weaker than the receiver's own thermal noise.
  • All satellites transmit on the same frequency at the same time.
  • A clear "tick" is needed to measure arrival time precisely.
A single tool, the PRN code, solves all three. The rest of this deck shows how, step by step: first intuitively, then with the math, then with a live simulation.

Part I — The signal

The problem: the signal is weaker than the noise

Imagine trying to hear one person whispering in a packed stadium. You can do it if you know exactly what sentence they are whispering: you listen for that one pattern and ignore everything else. A GPS receiver does the same with the PRN code.

A GPS satellite orbits about 20,200 km up and transmits about 27 dBW EIRP. After free-space loss, the guaranteed minimum received L1 C/A power is

\[ C = -158.5\ \text{dBW} = -128.5\ \text{dBm}. \]

The thermal noise density at \(T_0 = 290\,\text{K}\) is \(N_0 = kT_0 = -174\ \text{dBm/Hz}\), which gives

\[ \frac{C}{N_0} = -128.5-(-174) \approx 45.5\ \text{dB-Hz} \] \[ \text{SNR}_{B=2\,\text{MHz}} = \frac{C}{N_0\,B} = 45.5 - 63.0 = -17.5\ \text{dB}. \]
In the receiver's 2 MHz front-end bandwidth the noise is about 56× stronger than the signal. A spectrum analyzer shows only the noise floor. The PRN code is what lets the receiver recover the signal anyway.

Part I — The signal

A PRN code does three jobs at once

Picture a party where every pair of guests speaks a different language. You hear everyone at once but understand only your own (that is CDMA). And if you know the song a satellite is "singing", hearing how far behind its version you are tells you the travel time (that is ranging).

① Multiple access (CDMA)

All GPS satellites transmit on the same 1575.42 MHz carrier. Each has its own code \(c_k\), and the codes are nearly orthogonal (\(R_{ij}\approx 0\)), so correlating with \(c_k\) picks out satellite \(k\) only.

② Ranging (a time stamp)

The code is deterministic and tied to GPS time. Its phase at reception tells the receiver when it was sent. The sharp autocorrelation peak (one chip ≈ 293 m wide) makes that timing precise to well under a metre.

③ Processing gain

Correlation gathers energy spread over about 2 MHz back into the 50 Hz data bandwidth: \(10\log_{10}(1.023\cdot10^6/50)\approx 43\) dB. This lifts the signal out of the noise and suppresses narrowband interference.

CDMA: one carrier, many codes, a bank of correlators
Each correlator multiplies \(r(t)\) by its own replica and integrates. Only the matching satellite gives a peak; the others leave a residue at the level of the cross-correlation (≈ −24 dB).
Part I — The signal

The L1 C/A signal: carrier × code × data

The transmitted signal is three things multiplied together: a fast radio wave (the carrier) that crosses space, a fast ±1 pattern (the code) that identifies the satellite and marks time, and a slow ±1 message (the data) carrying orbit and clock information. Multiplying a wave by −1 just flips it upside down.
\[ s_k(t)=\sqrt{2P}\;C_k(t)\,D_k(t)\,\cos\!\left(2\pi f_{L1}t+\theta_k\right) \] \[ C_k(t)=\sum_{n}c_k\!\left[n \bmod 1023\right]\,p\!\left(t-nT_c\right),\quad c_k[n]=\pm1 \]

\(p(t)\) is a rectangular pulse of width \(T_c\). Every clock is derived from one atomic reference, \(f_0 = 10.23\) MHz:

Carrier \(f_{L1}\)\(154\,f_0\)1575.42 MHz
Chip rate \(R_c\)\(f_0/10\)1.023 Mchip/s
Chip length \(T_c\)\(1/R_c\) → \(cT_c\)977.5 ns → 293.05 m

This is BPSK modulation: each sign change of \(C_k D_k\) flips the carrier phase by 180°.

Part II — The code

Generating the code: two 10-stage shift registers

A shift register is a row of 10 one-bit memory cells. On every clock tick each cell passes its bit one place to the right, and the new leftmost bit is the XOR of a few chosen cells. With the right choice of cells the pattern repeats only after 1023 ticks. Press Clock ×1 to watch it.

The C/A code comes from two linear feedback shift registers (LFSRs). Their characteristic polynomials over GF(2) are

\[ G_1(x)=1+x^{3}+x^{10} \] \[ G_2(x)=1+x^{2}+x^{3}+x^{6}+x^{8}+x^{9}+x^{10} \]

which, as recurrences, are

\[ g_1[n]=g_1[n-3]\oplus g_1[n-10] \] \[ \begin{aligned} g_2[n]=\;&g_2[n-2]\oplus g_2[n-3]\oplus g_2[n-6]\\ &\oplus g_2[n-8]\oplus g_2[n-9]\oplus g_2[n-10] \end{aligned} \]

Both polynomials are primitive, so each register cycles through all \(2^{10}-1=1023\) non-zero states (an m-sequence). Both start at all ones each epoch. Every satellite uses the same G1 and G2; only the two G2 phase-selector taps differ from PRN to PRN.

Gray boxes are register stages 1–10. Bottom buses: feedback taps. Blue: the PRN's phase-selector taps \((s_1,s_2)\) on G2. Output chip = G1 stage 10 ⊕ G2 stage \(s_1\) ⊕ G2 stage \(s_2\).
Part II — The code

Gold codes: one family, many PRNs

All satellites use the same two registers. Each PRN reads G2 from a different pair of cells, which amounts to a different time offset of the G2 sequence. Combining G1 with differently delayed copies of G2 gives 32 (up to 1025) codes that all look unrelated to one another.

XOR-ing two G2 stages produces a delayed copy of the G2 m-sequence. This is the shift-and-add property of m-sequences:

\[ g_2[n-s_1]\oplus g_2[n-s_2] = g_2[n-\Delta_k] \] \[ \boxed{\,c_k[n]=g_1[n]\oplus g_2[n-\Delta_k]\,} \]

Adding a preferred pair of m-sequences at a relative delay \(\Delta_k\) gives a Gold code. The family has \(2^{10}+1=1025\) members, and every cross-correlation takes only three values:

\[ R_{ij}(\tau)\in\left\{-1,\;-t(10),\;t(10)-2\right\}=\{-1,-65,63\} \] \[ t(n)=2^{\lfloor (n+2)/2\rfloor}+1 = 65\ \ (n=10) \]

Bits map to signal levels by \(x = 1-2b\) (0 → +1, 1 → −1). Under this map XOR becomes multiplication: \(b_1\oplus b_2 \mapsto x_1x_2\).

Part II — The code

It looks like noise, but it is fully deterministic

A statistician handed this sequence would say it passes basic randomness tests. Yet it is completely predictable, so the receiver can generate the exact same sequence. That is what "pseudo-random" means.

Over one period, a good spreading code looks like a random coin-toss sequence:

  • Balance. Ones and zeros differ in count by at most one. In the ±1 domain the mean is \(\bar c = \frac1N\sum_n c[n] = \pm\frac{1}{1023}\), so there is almost no DC (carrier-leak) component.
  • Run lengths. Short runs are common and long runs rare, roughly halving for each extra chip of run length, as in a random sequence.
  • Repeatability. Unlike real noise, the receiver can generate the identical sequence locally. That is what makes correlation possible.

Part II — The code

What correlation does: multiply chip by chip, then add

Correlation is the receiver's basic operation. It takes the received chips and its own locally generated copy of the code (the replica), multiplies them one by one, and adds up the products. When the replica is aligned, every product is (+1)(+1) or (−1)(−1) = +1, so the sum is 1023. When it is off by even one chip, the products are a near-random mix of +1 and −1 that cancel, and the sum stays near 0.
\[ \text{corr}(k)=\sum_{n=0}^{1022} r[n]\;c\big[(n-k)\bmod 1023\big] \] \[ \text{aligned: }\ \sum 1 = 1023\qquad\text{misaligned: }\ \in\{-65,\,-1,\,63\} \]

The received code in this demo is delayed by 12 chips. Move the replica and watch the products and the sum.

Turn the noise up to σ = 3 (individual chips are now unreadable). The aligned sum (~1023) still towers over the noise in the sum (σ√1023 ≈ 96). That is processing gain at work, covered in Part III.

Part II — The code

Autocorrelation: one peak, small sidelobes

Now do the correlation from the previous slide for every possible shift. You get one tall spike where the code lines up with itself, and small values everywhere else (at most 65 out of 1023). So the question "am I aligned?" has a clear yes/no answer.

Correlating the code with a cyclically shifted copy of itself gives

\[ R_k(\tau)=\frac{1}{N}\sum_{n=0}^{N-1}c_k[n]\,c_k\!\left[(n+\tau)\bmod N\right] \] \[ R_k(0)=1,\qquad R_k(\tau\neq0)\in\left\{-\tfrac{1}{1023},\,-\tfrac{65}{1023},\,+\tfrac{63}{1023}\right\} \]

The ratio of the main peak to the largest sidelobe is

\[ 20\log_{10}\frac{1023}{65}\approx 23.9\ \text{dB}. \]

Why it matters: when a local replica is aligned within one chip the receiver sees the full signal energy; anywhere else it sees almost none. Code alignment is therefore detectable, and that is the basis of acquisition (Part IV).

Part II — The code

Zooming in: the correlation triangle

Between "perfectly aligned" and "one chip off", the match falls off linearly, like the sides of a tent. Because the sides slope, the receiver can tell not only whether it is aligned but which way and by how much it is off. That is how it measures distance far more finely than one chip (293 m).

With rectangular chips and continuous delay \(\tau\), the peak becomes a triangle two chips wide:

\[ R(\tau)\approx\begin{cases}1-\dfrac{|\tau|}{T_c}, & |\tau|\le T_c\\[4pt] \approx -\tfrac{1}{N}\ \text{(or a sidelobe)}, & |\tau|\gt T_c\end{cases} \]

The triangle's slope is the ranging lever. A delay error \(\Delta\tau\) changes the correlation by \(\Delta\tau/T_c\), and the tracking loop (Part V) uses that change to hold the replica on the peak.

Part II — The code

Cross-correlation: keeping satellites apart

Correlate satellite 1's replica against satellite 2's signal and you get only small, noise-like values, never a spike. This is how one receiver listens to 10 or more satellites on the same frequency at the same time.
\[ R_{ij}(\tau)=\frac{1}{N}\sum_{n=0}^{N-1}c_i[n]\,c_j\!\left[(n+\tau)\bmod N\right]\in\frac{\{-1,-65,63\}}{1023} \]

Any two C/A codes leak at most \(65/1023\), which is −23.9 dB. That is the CDMA isolation between satellites, and it is limited:

Near–far problem. If satellite \(j\) is received about 20 dB stronger than satellite \(i\) (for example, high elevation vs. a blocked low one), a cross-correlation spike of \(c_j\) in the \(c_i\) search can be about as large as \(i\)'s true peak. Receivers must check acquisitions for false locks of this kind. Doppler offsets between satellites make the cross-correlation slightly worse again (the limit is about −21 dB).

Part II — The code

The spectrum: sinc² envelope, 1 kHz lines

Switching between +1 and −1 a million times per second spreads the signal's power over about 2 MHz, so the power in any 1 Hz slice is tiny. That is why the signal hides under the noise. Because the code repeats every 1 ms, the spectrum is really a comb of lines 1 kHz apart.

The code repeats every \(T=1\) ms, so its spectrum is a set of lines spaced \(1/T = 1\) kHz. Their envelope follows the spectrum of a single rectangular chip:

\[ S_C(f)=\sum_{m}\left|a_m\right|^2\,\delta\!\left(f-\frac{m}{T}\right) \] \[ |a_m|^2\approx\frac{1}{N}\,\mathrm{sinc}^2\!\left(\pi\,\frac{m}{T}\,T_c\right) \] \[ \text{null-to-null bandwidth}=2R_c=2.046\ \text{MHz} \]
  • About 90% of the power lies in the main lobe, \(|f|\lt 1.023\) MHz.
  • Each line holds about \(1/1023\) of the power (−30 dB). The DC line holds only \((1/1023)^2\) (−60 dB) because the code is balanced.
  • Spreading lowers the peak spectral density by \(10\log_{10}(R_c/R_b)\). This is why the signal sat under the noise floor in the first plot of Part I.

Part III — Spreading & despreading

Despreading: multiply by the code again

Multiply by the code twice and you get back what you started with, because (±1)² = 1. Noise multiplied by the code is still just noise. Adding up many chips then grows the signal ×L but the noise only ×√L. That is how a signal below the noise is recovered.

Because \(c[n]^2 = 1\), multiplying by the aligned replica undoes the spreading. The noise, which is uncorrelated with the code, stays noise:

\[ r[n]=d[n]\,c[n]+w[n]\ \Longrightarrow\ c[n]\,r[n]=d[n]+\underbrace{c[n]\,w[n]}_{\text{still white}} \] \[ z_m=\sum_{n\in\text{bit }m}c[n]\,r[n]=L\,d_m+\mathcal N\!\left(0,\,L\sigma^2\right) \]

Summing \(L\) chips adds the signal coherently (×\(L\) in amplitude) and the noise incoherently (×\(\sqrt L\)), so the SNR improves by a factor of \(L\). This is the processing gain:

\[ G_p=\frac{R_c}{R_b}=\frac{1.023\times10^{6}}{50}=20460\;\Rightarrow\;43.1\ \text{dB} \]

Part III — Spreading & despreading

Processing gain: the number that makes GPS work

Processing gain is how much the signal-to-noise ratio improves when the receiver correlates, that is, multiplies by the code and sums. Each chip carries a little signal and a lot of noise. Adding up N chips makes the signal N times bigger, but random noise grows only √N times, so the power SNR improves by a factor of N. It is the same reason averaging many noisy measurements gives a precise answer.
\[ G_p=\frac{B_{\text{spread}}}{B_{\text{despread}}}=\frac{R_c}{1/T}=R_c\,T\;=\;N_{\text{chips summed}} \] \[ \text{SNR}_{\text{out}}\,[\text{dB}]=\text{SNR}_{\text{chip}}\,[\text{dB}]+10\log_{10}G_p \] \[ \text{SNR}_{\text{out}}=\frac{C}{N_0R_c}\cdot R_cT=\frac{C}{N_0}\,T \]

The spreading bandwidth cancels: what counts in the end is only C/N₀ and how long the receiver integrates.

Part III — Spreading & despreading

In the frequency domain: what despreading does to interference

Despreading is selective. It squeezes the matching GPS signal into a narrow peak and smears everything else, jammers included, thinly across 2 MHz. A narrow filter then keeps the peak and throws away most of the smeared interference. This is processing gain seen in the frequency domain.

Multiplying by \(c(t)\) convolves every spectrum with the code's spectrum. That operation collapses the matched signal into a narrow line and spreads everything else, including a narrowband interferer, across about 2 MHz.

\[ \left(\frac{S}{J}\right)_{\text{out}}\approx\left(\frac{S}{J}\right)_{\text{in}}+G_p \] \[ \left(\frac{J}{S}\right)_{\max}=G_p-\left(\frac{S}{N}\right)_{\text{req}}-L_{\text{sys}} \]

Example: a CW interferer 30 dB stronger than the GPS signal. After despreading, only the fraction of its power that falls inside the 50 Hz data bandwidth matters:

\[ \left(\frac{J}{S}\right)_{\text{out}} \approx +30 - 43.1 = -13.1\ \text{dB} \]

The signal ends up 13 dB above an interferer that started 30 dB stronger. That 43 dB swing is the processing gain.

Part IV — Acquisition

Acquisition: a 2-D search over code phase and Doppler

Before it can track anything, the receiver must find out which satellites are present, where in their code they are, and how much they are Doppler-shifted. It is like tuning an old radio without knowing the station's frequency or when its program started. The receiver tries every combination of time offset and frequency and looks for the one cell that lights up.

For each candidate PRN \(k\), code phase \(\hat\tau\) and Doppler \(\hat f\), the receiver correlates over a coherent interval \(T_{coh}=NT_s\):

\[ I+jQ=\sum_{n=0}^{N-1}r[n]\;c_k\!\left(nT_s-\hat\tau\right)\,e^{-j2\pi\hat f\,nT_s} \] \[ S_k(\hat\tau,\hat f)=I^2+Q^2\quad\text{(phase-independent)} \] \[ \bar S_k=\sum_{m=1}^{K}S_k^{(m)}\quad\text{(non-coherent sum of }K\text{ blocks)} \]

Part IV — Acquisition

How fine must the grid be? Doppler and code-phase losses

If the frequency guess is a bit off, the signal's phase drifts during the sum and partly cancels itself. If the code guess is a fraction of a chip off, the receiver lands on the side of the tent instead of the top. The grid spacing trades search effort against lost signal.

A residual frequency error \(\Delta f\) makes the phasor rotate during the integration, so the coherent sum partly cancels:

\[ \left|\frac{1}{T}\int_0^{T}e^{j2\pi\Delta f t}\,dt\right|^2=\mathrm{sinc}^2(\pi\,\Delta f\,T_{coh}) \]

A code-phase error \(\Delta\tau\) samples the triangle off its peak:

\[ L_\tau=\left(1-\frac{|\Delta\tau|}{T_c}\right)^2 \]

Signal present or not? Detection theory

This is like setting a smoke alarm's sensitivity. Set the threshold too low and noise alone triggers false alarms; set it too high and real signals are missed. The two curves show the correlator output with and without a signal. More integration time (more processing gain) pulls them apart.

Part V — Tracking

Code tracking: Early – Prompt – Late

Three correlators sit slightly early, on time (prompt) and slightly late. If early and late see equal correlation, the prompt one is on the peak. If late sees more, the replica is running ahead of the true signal, and the loop delays it until they balance, like a balance scale.

Once acquired, a delay lock loop keeps the replica on the peak. Three replicas are correlated, offset by \(\pm d/2\) chips (\(\varepsilon=\hat\tau-\tau\)):

\[ E=R\!\left(\varepsilon-\tfrac d2\right),\quad P=R(\varepsilon),\quad L=R\!\left(\varepsilon+\tfrac d2\right) \] \[ D(\varepsilon)=\frac{2-d}{2}\cdot\frac{|E|-|L|}{|E|+|L|}\ \approx\ \varepsilon\quad\text{for }|\varepsilon|\lt\tfrac d2 \] \[ \hat\tau_{k+1}=\hat\tau_k-K_{\text{loop}}\,\bar D_k \]

The normalized early-minus-late envelope discriminator is insensitive to carrier phase and to signal amplitude. Its linear range is \(\pm d/2\) and its pull-in range is \(\pm(1+d/2)\) chips.

Part V — Tracking

Carrier tracking: the Costas loop and bit recovery

The code loop keeps the timing; this loop keeps the replica carrier in phase with the incoming carrier. When locked, all the energy sits on the I axis and the sign of I is the data bit. The Costas trick keeps working even though the data bits keep flipping the sign.

After code wipe-off with the prompt replica, the integrate-and-dump outputs are

\[ I_P=\tfrac{A}{2}\,D\,R(\varepsilon)\cos\theta_e+n_I,\qquad Q_P=\tfrac{A}{2}\,D\,R(\varepsilon)\sin\theta_e+n_Q \] \[ D_{\text{Costas}}=\arctan\!\left(\frac{Q_P}{I_P}\right)=\theta_e\quad(|\theta_e|\lt\pi/2) \]

The data sign \(D=\pm1\) cancels in \(Q_P/I_P\), so the loop tolerates bit flips. The price is a 180° ambiguity, which is resolved later with the navigation preamble. When locked, the bits are simply \(\hat D=\mathrm{sign}(I_P)\).

The tracked Doppler also aids the DLL: \(f_{\text{code}}=R_c\,(1+f_D/f_{L1})\).

Part VI — Measurement & evaluation

From code phase to pseudorange

The code phase gives the fraction of the current millisecond; counting whole milliseconds (using the data bits) gives the rest. Multiply the total travel time by the speed of light to get the range. It is called pseudorange because the receiver's clock is off by an unknown amount, which is solved for along with position.

The tracked code phase gives the satellite's transmit time, read from the received signal:

\[ t_{tx,k}=\underbrace{\text{TOW}}_{\text{subframe}}+\underbrace{N_{ms}\cdot 1\,\text{ms}}_{\text{bit/epoch count}}+\underbrace{\hat\tau_k/R_c}_{\text{DLL}} \] \[ \rho_k=c\,(t_{rx}-t_{tx,k})=\|\mathbf r_k-\mathbf r_u\|+c\,(\delta t_u-\delta t^{k})+I_k+T_k+\varepsilon_k \]
  • The code phase alone is ambiguous modulo 1 ms (299.79 km). Bit synchronization (20 ms) and the subframe TOW (6 s) resolve the whole milliseconds.
  • \(\delta t_u\), the receiver clock bias, is the same for all satellites. It is the fourth unknown, which is why a fix needs at least 4 PRNs.
  • \(I_k, T_k\): ionospheric and tropospheric delays. \(\varepsilon_k\): noise and multipath, the terms the code design directly affects.
Timing picture: code epochs as a clock
Each 1 ms code epoch is a tick on the satellite's clock. The receiver counts whole epochs (via bit and frame sync) and measures the fractional part with the DLL to sub-chip precision.
Part VI — Measurement & evaluation

How precise is the code measurement?

Noise makes the measured peak position jitter. More signal, a slower (narrower-bandwidth) loop, or more closely spaced early/late correlators all reduce the jitter, taking code ranging from metres down to centimetres.

Thermal-noise jitter of a non-coherent early-minus-late power DLL (rectangular chips, infinite bandwidth):

\[ \sigma_\tau=\sqrt{\frac{B_n\,d}{2\,C/N_0}\left[1+\frac{2}{(2-d)\,T_{coh}\,C/N_0}\right]}\ \ \text{chips} \] \[ \sigma_\rho=\sigma_\tau\cdot 293.05\ \text{m} \]
  • \(B_n\): loop noise bandwidth. Narrower averages more noise but follows dynamics more slowly.
  • \(d\): early–late spacing. A narrow correlator (\(d=0.1\)) cuts jitter by about \(\sqrt{10}\).
  • The bracketed term is the squaring loss, which matters only at low C/N₀.
The Cramér–Rao bound links precision to the signal's RMS bandwidth \(\beta\): \(\sigma_\tau\ge 1/\big(2\pi\beta\sqrt{2\,T\,C/N_0}\big)\). Codes with faster chipping or sharper spectra, such as L5 (10.23 Mcps) or BOC, have a larger β and range more precisely.

Part VI — Measurement & evaluation

Multipath: a second triangle bends the peak

An echo off a building or the ground arrives slightly late and adds a second, smaller tent. The combined shape is lopsided, so the early/late balance point shifts and the range comes out wrong, by up to tens of metres. Echoes more than about 1.5 chips (~450 m of extra path) late miss the tent and do no harm.

A reflection with relative amplitude \(\alpha\), extra delay \(\delta\) and phase \(\phi\) adds a delayed copy of the correlation function:

\[ R_c(\tau)=R(\tau)+\alpha\cos\phi\;R(\tau-\delta) \] \[ \text{lock point: } \big|R_c(\varepsilon-\tfrac d2)\big|=\big|R_c(\varepsilon+\tfrac d2)\big|\ \Rightarrow\ \varepsilon_{mp}(\alpha,\delta,\phi,d) \]

The DLL balances E and L on a distorted triangle, so the lock point moves away from the true peak. The resulting range error is largest for reflections delayed by about \(d/2\) to \(1\) chip. Reflections beyond \(1+d/2\) chips have no effect. This is the code's built-in multipath rejection.

Part VI — Measurement & evaluation

Evaluating the signal: C/N₀ and quality monitors

Receivers continuously report how strong each signal is (C/N₀) by comparing how much the prompt output adds up coherently versus how much power it has in total. Quality monitors check the tent's shape for distortions that would point to a satellite fault, multipath or interference.

The prompt correlator also gives the receiver's main signal-quality metric. The narrowband–wideband power ratio (NWPR) estimator, over \(M\) dumps of length \(T\) within one data bit:

\[ \text{WBP}=\sum_{i=1}^{M}\left(I_i^2+Q_i^2\right),\quad \text{NBP}=\Big(\sum_{i=1}^{M}I_i\Big)^2+\Big(\sum_{i=1}^{M}Q_i\Big)^2 \] \[ \hat\mu=\Big\langle \tfrac{\text{NBP}}{\text{WBP}}\Big\rangle_K,\qquad \widehat{C/N_0}=10\log_{10}\!\left(\frac{1}{T}\,\frac{\hat\mu-1}{M-\hat\mu}\right) \]

Other correlator-based evaluations:

  • PLL lock detector: \(\cos2\theta_e\approx\frac{(\sum I)^2-(\sum Q)^2}{(\sum I)^2+(\sum Q)^2}\) (≈1 when locked).
  • Signal-quality monitoring (SQM): several correlator pairs at spacings \(d_i\) give symmetry tests \(\Delta_i=\frac{E_i-L_i}{P}\) and ratio tests \(\frac{E_i+L_i}{P}\). These detect distorted "evil waveforms" and multipath (see the 1993 SVN19 anomaly).
  • Cross-correlation check: reject a "lock" whose C/N₀ is about 24 dB below a strong satellite at a code/Doppler offset where a cross-correlation spike is expected.

Newer signals use longer codes (better separation between satellites and more processing gain per code period), faster chips (a sharper tent, so better precision), and data-free "pilot" components that allow longer summing for weak signals.

Summary

The PRN code at every stage of the receiver

Generate

\(c_k[n]=g_1[n]\oplus g_2[n-\Delta_k]\). Gold family; balanced, noise-like, reproducible.

Correlate

\(R_k(0)=1\), \(|R_k(\tau\neq0)|,|R_{ij}|\le 65/1023\). Gives CDMA separation and a 43 dB processing gain.

Acquire

Search \(S(\hat\tau,\hat f)=I^2+Q^2\) over 1023 chips × ±10 kHz. FFT makes it fast; Rayleigh/Rice statistics set the threshold.

Track

The E−L discriminator on the triangle \(1-|\tau|/T_c\) (DLL), and \(\arctan(Q_P/I_P)\) for the carrier (Costas).

Measure

\(\rho=c(t_{rx}-t_{tx})\) with \(t_{tx}\) from TOW + ms count + code phase. Jitter \(\propto\sqrt{B_n d/(C/N_0)}\).

Evaluate

C/N₀ (NWPR), lock detectors, SQM symmetry tests, cross-correlation checks, multipath envelopes.
